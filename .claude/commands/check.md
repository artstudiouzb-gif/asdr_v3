---

Прогони проверки проекта и коротко доложи результат. Не чини ничего без отдельной просьбы — сначала покажи, что нашлось.

1. **Тесты** (переменные TEST_DB_* уже экспортированы хуком старта сессии; если их нет — подставь `TEST_DB_HOST=127.0.0.1 TEST_DB_DATABASE=artstudio_test TEST_DB_USERNAME=root TEST_DB_PASSWORD=`):

   ```bash
   php tests/run.php
   ```

2. **Статический анализ.** `composer analyse` в этой среде не проходит (нет авторизации GitHub), поэтому запускай phar, который кладёт хук:

   ```bash
   php storage/tools/phpstan.phar analyse --no-progress
   ```

   Если файла нет — скажи об этом и пропусти шаг, не пытайся ставить composer.

3. **Собранные ассеты** — только если менялись `public/assets/css/*.css` или `public/assets/js/*.js` вне `*.min.*`:

   ```bash
   npm run check:assets
   ```

   Расходится — пересобери `npm run build:assets` и скажи, что пересобрал.

4. **Бюджеты качества** — только если менялись CSS, разметка админки или
   `phpstan-baseline.neon`:

   ```bash
   php .claude/skills/quality-budgets/report.php
   ```

   Строка «запас — опустить» значит, что потолок отстал от факта: скажи об этом,
   но не правь без просьбы. Подробности — скилл `quality-budgets`.

В ответе: число пройденных и упавших тестов, вердикт PHPStan, состояние ассетов,
превышенные или отставшие бюджеты. Упавшее — с именем теста и причиной, без пересказа остального вывода.
