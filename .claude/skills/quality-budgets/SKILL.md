# Бюджеты качества

В проекте несколько величин, про которые договорено: **они могут только
уменьшаться**. У каждой стоит свой сторож в `tests/cases`, и это правильно —
падать должно там, где нарушено. Но у сторожа есть слепое пятно: зелёный прогон
не печатает ни текущего значения, ни потолка. «Уже нарушено?» он отвечает,
«сколько ещё можно?» — нет, а именно этот вопрос задают перед правкой.

Отчёт закрывает второй вопрос:

```bash
php .claude/skills/quality-budgets/report.php            # таблица
php .claude/skills/quality-budgets/report.php --json     # для скриптов
php .claude/skills/quality-budgets/report.php --strict   # код 1 при превышении
```

Базы данных не требует, считает по файлам репозитория, идёт секунды.

## Где что объявлено

Потолок и способ замера лежат **в одном месте** — `tests/budgets.php`. Оттуда их
читают и сторожа в `tests/cases`, и этот отчёт. Второй список тех же чисел
разъехался бы с первым молча — ровно тот случай, ради которого настройка блока
объявляется один раз в схеме полей.

| Бюджет | Сторож |
|---|---|
| `!important` в публичном CSS | `tests/cases/262_css_hygiene_test.php` |
| `!important` в CSS админки | `tests/cases/279_admin_typography_scale_test.php` |
| `!important` в дизайн-системе темы | `tests/cases/236_design_scale_drift_test.php` |
| Разных статичных `font-size` в теме | `tests/cases/236_design_scale_drift_test.php` |
| Разных `box-shadow` в теме | `tests/cases/236_design_scale_drift_test.php` |
| Разных `border-radius` в теме | `tests/cases/236_design_scale_drift_test.php` |
| Классы админки без правил | `tests/cases/278_admin_dead_classes_test.php` |
| Жёсткие `border-radius` мимо настройки | `tests/cases/309_radius_setting_reach_test.php` |
| Находки в эталоне PHPStan | `tests/cases/293_phpstan_baseline_budget_test.php` |
| Вес `public.min.css` / `.js` | `npm run check:assets` |

Вес бандлов меряется brotli качества 11 — тем же, что считает сборка; потолок
вычитывается из `scripts/build-assets.mjs`, а не копируется. Brotli в PHP нет,
поэтому считает `node`: нет node — строка честно говорит «не измерено», а не
показывает ноль как «уложились». Отчёт меряет **собранный** бандл, свежесть
которого проверяет `npm run check:assets`.

## Как читать таблицу

Колонка «Статус» устроена не так, как ждёшь: **запас — это не «хорошо»**.
Невыбранный храповик рано или поздно израсходует случайная правка, поэтому
окликается как раз строка с запасом.

| Статус | Что значит | Что делать |
|---|---|---|
| `по факту` | потолок равен текущему числу | ничего, храповик взведён |
| `запас — опустить` | чистка ушла дальше потолка | опустить потолок в том же коммите |
| `ПРЕВЫШЕН` | сторож уже упал или упадёт | чинить, а не поднимать планку |
| `не измерено` | нет node или нет файла | сказать об этом, а не считать пройденным |
| `ок` (вес бандлов) | под потолком | ничего: там запас поставлен сознательно |

Вес бандлов — единственная строка, где запас законен: порог не должен дёргать
на каждый килобайт, он ловит аварию вроде несжатого вендорного файла.

## Как этим пользоваться

**Перед PR.** Прогнать отчёт. Строка `ПРЕВЫШЕН` — правка не пройдёт CI; строка
`запас — опустить` — потолок отстал от факта, и его надо подтянуть, пока запас
не израсходовали за тебя.

**Превышение чинят, а не легализуют.** Поднять потолок можно, но в том же
коммите объяснив, чем рост оправдан. «Подняли, чтобы прошло» — не объяснение:
смысл бюджета в том, чтобы разговор состоялся до слияния, а не задним числом
(так однажды набрались 419 КБ полутора десятками дизайн-коммитов подряд).

**Первый же прогон нашёл четыре отставших потолка**: `!important` в публичном
CSS 370 при факте 366, тени 161 при 156, радиусы 36 при 32, `!important` темы
384 при 320 — чистка была сделана, а храповик за ней не сдвинули. Все четыре
опущены под факт.

## Порядок уборки (проверен на слое «Enterprise Scale»)

Снимать `!important` пачкой нельзя: для части компонентов этот слой —
единственное место, где они вообще оформлены. Порядок такой:

1. правило переносится в компонент **или** получает честный вес селектора
   (исключение пишется через `:not(:where(.btn))` — голый `:not()` поднимает вес);
2. только потом снимается `!important`;
3. **срез вычисленных стилей доказывает, что вид не поехал**:
   `node scripts/admin-style-snapshot.mjs before|after|--diff` для админки,
   `npm run test:visual` для публички.

Читать код вместо замера здесь нельзя: тема грузится после базы и перекрывает
её, а правило, где значение написано числом, переменную не слушает вовсе.

## Новый бюджет

Добавляется в `quality_budgets()` (`tests/budgets.php`): заголовок, единица,
сторож, объяснение «почему», потолок и замер. Замер возвращает `value` и
`detail` — по `detail` при падении сразу видно, куда смотреть. Потолок ставится
**по факту на момент заведения**, а не с запасом: запас — это разрешение
деградировать.

Сторож после этого читает `quality_budget('<id>')` и сравнивает `value` с
`ceiling`. Своих чисел в тесте быть не должно.

## Чего этот скилл не делает

Не заменяет тесты: отчёт ничего не роняет сам по себе (кроме `--strict`).
Не проверяет то, что бюджетом не является, — общая шкала точек перелома,
шкала `--step-*`, отсутствие `text-wrap: balance`: там не потолок, а закрытый
список, и стерегут их те же тесты по-своему.
