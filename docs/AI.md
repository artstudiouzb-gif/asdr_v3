# Помощник-модель в админке

ИИ в системе один — **Google Gemini**, ключ хранится секретом
(`ai_api_key`, «Настройки сайта» → ИИ-интеграция). Ключа нет — панель работает
как раньше: каждая задача либо честно говорит, что интеграция не настроена,
либо отдаёт локальный результат (анонс и SEO считаются разбором текста без
всякой модели).

## Правила, из которых всё выведено

1. **Только админка и cron.** Публичная страница в сеть не ходит вовсе — это
   условие доступности, а не пожелание (замерено: блокирующий запрос к чужому
   API давал 733 мс против 37 мс). Тест 381 проверяет, что `App\Core\Ai` не
   упоминается ни в публичных вьюхах, ни в контроллерах сайта, ни в шаблонах.
2. **Модель предлагает, публикует человек.** Ни одна задача ничего не
   публикует и не перезаписывает готовый текст: результат попадает в поле формы
   или в список замечаний.
3. **Присланный материал — данные, а не инструкции.** Оговорка объявлена один
   раз (`AiClient::DATA_RULE`) и добавляется ко всем задачам сразу: «игнорируй
   предыдущее» внутри новости не должно становиться командой.
4. **Персональные данные наружу не уходят.** Заявки форм, адреса подписчиков и
   содержимое запросов к модели не отправляются. Разбор записи журнала
   отправляет только сам текст ошибки и доступен супер-админу — в журнале
   видны пути на диске и внутренние сообщения.
5. **Один и тот же вход не оплачивается дважды.** Ответ лежит в кэше сутки,
   повторное нажатие кнопки ничего не стоит; на пользователя — не больше 60
   задач в час (`RateLimiter`).
6. **Отказ не роняет вызывающего.** Модель не ответила — задача возвращает
   пустой результат и строку с объяснением, а исход уходит в «Состояние
   системы» (ключ `ai`).

## Что умеет

| Задача | Где | Что делает |
| --- | --- | --- |
| Анонс и хештеги | форма новости | редакционный анонс вместо копии первых строк |
| SEO-заголовок и описание | форма новости, форма страницы | `meta_title` / `meta_description` по заголовку и тексту |
| Вычитка | форма новости | замечания по самому тексту: заголовок не о том, лид повторяет абзац, канцелярит |
| Рубрика и метки | форма новости | рубрика **из заведённых**, метка карточки, хештеги |
| Alt-текст | медиатека, «Производительность» → «Изображения» | описание снимка для незрячих: по одному файлу или пакетом |
| «Что это значит» | «Журналы» → ошибки | разбор записи журнала для владельца, который не инженер |
| Каркас страницы | «Шаблоны страниц» | структура страницы по описанию → шаблон в библиотеке |

Каркас страницы разбирается тем же `PageTemplateFile::parse`, что и присланный
файл: ответ модели — такой же внешний источник, как чужая выгрузка. Блок
«HTML» и свой CSS оттуда не пройдут, применение к странице остаётся отдельным
действием редактора.

Пакетная подпись изображений идёт **пакетами с курсором** (тот же бегунок, что
у достройки миниатюр и починки прав) и останавливается в любой момент: за
каждым снимком стоит обращение к модели, поэтому пробный проход сначала
показывает объём работы.

## Как добавить новую задачу

1. Класс в `app/Core/Ai/` — только задача: что просим, по какой схеме и как
   разбираем ответ. Запрос делает `AiClient::json()`, своего обращения к API в
   задаче быть не должно (тест 381 проверяет, что адрес API назван ровно в
   одном файле).
2. Метод в `App\Controllers\Admin\AiController` начинается с `$this->begin()` —
   доступ, CSRF, ограничитель частоты, заголовок ответа. Задаче, которая видит
   служебные данные, — `$this->begin(true)` (супер-админ).
3. Маршрут `POST /admin/ai/<задача>` в `public/index.php`. GET не заводим:
   запрос к модели стоит квоты, и дёргать его ссылкой нельзя.
4. Кнопка в разметке: `data-ai-task="<задача>"` плюс, по надобности,
   `data-ai-target`, `data-ai-report`, `data-ai-into`, `data-ai-kind`. Общий
   обработчик в `admin.js` сам соберёт поля формы и разложит ответ — своего
   `fetch` рядом писать не нужно.
5. Локальное поведение без ключа обязательно: либо запасной результат, либо
   строка `notice` с причиной. Кнопка, которая молча ничего не делает, — худший
   вид отказа.
