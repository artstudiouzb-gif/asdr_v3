# Блоки конструктора страниц

Справочник по всем типам блоков: что блок делает, чем настраивается, откуда
берёт данные. Источник истины — `app/Core/BlockTypeRegistry.php` (ключи типов и
поля), шаблоны — `templates/blocks/{type}.php`, поля редактора —
`app/Views/admin/pages/block_form.php`, приём формы —
`app/Controllers/Admin/BlockController.php::collectData()`.

**Настройки типа со схемой объявляются один раз.** У типов, переехавших на
`App\Core\BlockData\BlockFieldSchema` (сейчас 33 из 37; по-старому остались
`text`, `html`, `form`, `hero`), описание поля — тип значения, границы,
умолчание, подпись, подсказка — лежит только в схеме. Из него получаются
умолчания реестра, поле формы, нормализация присланного и проверка данных на
выводе (`BlockFieldSchema::apply()`), поэтому шаблон читает `$data` как есть и
второй копии списка значений не содержит. Поимённый список здесь не ведётся
намеренно: он разъезжался с кодом при каждом переезде — актуальный отдаёт
`array_keys(BlockFieldSchema::all())`, а число непереехавших держит сторож
(бюджет `blocks_off_schema`, может только уменьшаться).
Остальные типы живут по-старому: умолчание в `BASE_DEFAULTS`, поле в форме,
ветка в `collectData()`, проверка в шаблоне — четыре места, которые молча
расходятся. Новую настройку у типа со схемой добавляют одной строкой в схему;
тип без схемы разумно перевести на неё заодно с правкой. Мимо схемы идут
репитеры (`items`) и значения, зависящие от соседнего поля (`ratio` у колонок):
их умолчания перечислены в `BlockFieldSchema::EXTRA`, сборка остаётся явной.

Всего типов: **37**.

## Общие настройки (есть у любого блока)

Хранятся в `data` блока со служебным префиксом `_` и обрабатываются в
`BlockRenderer::render()`, а не в шаблонах.

| Ключ | Что делает |
|---|---|
| `_spacing` | Пресет вертикальных отступов: `none` / `small` / `premium` / `max` |
| `_pad_top`, `_pad_bottom` | Независимые отступы сверху и снизу |
| `_bg` | Фон секции пресетом темы: `none` / `light` / `tint` / `navy` |
| `_bg_mode` | Своя заливка вместо пресета: `color` / `gradient` / `image` / `pattern`. Режим один — два фона на секции дают кашу |
| `_bg_color`, `_bg_gradient_*` | Свой цвет и градиент (два цвета + угол) |
| `_bg_image`, `_bg_repeat`, `_bg_overlay`, `_bg_position`, `_bg_fixed` | Фотография (затемнение, кадр, фиксация) или плитка-узор с размером повтора |
| `_bg_pattern*` | Встроенный узор: точки, сетка, диагональ, гирих; цвет, шаг и заметность |
| `_bg_light_text` | Светлый текст на тёмной заливке — правила уходят в scoped CSS по id секции |
| `_min_height` | Минимальная высота секции: `small` 320px / `medium` 480px / `large` 640px / `screen`. Пусто — по содержимому |
| `_surface` | Подложка: `flat` или `card` |
| `_fullwidth` | Растянуть секцию на всю ширину экрана |
| `_reveal` | Анимация появления: `fade`, `slide-up/left/right`, `zoom-in`, `stagger` |
| `_visible_from`, `_visible_to` | Расписание показа. Считается на сервере: блок вне окна не попадает в HTML, кэш страницы истекает к ближайшей границе |
| `_visible_device` | Ограничение по устройству — только CSS-классами, потому что кэш страницы общий |
| `custom_css` | Произвольный CSS, автоматически ограничивается селектором `#block-N` |

Заголовок первого уровня на странице один: на `h1` претендует `hero`, и
только первый — второй такой блок печатает `h2`.

## Записи из базы

Эти блоки не хранят контент, а собирают опубликованные записи разделов —
дублировать их вручную не нужно. Язык берётся из текущей локали.

| Тип | Название | Настройки | Источник |
|---|---|---|---|
| `news_latest` | Последние новости | лимит, рубрика, текст и адрес ссылки «Все» | `news` |
| `news_feature` | Новости и аналитика | вариант (карточки / мозаика), лимит, рубрика, ссылка «Все» | `news` |
| `news_docs` | Новости + документы | лента слева (лимит, рубрика), ручной список документов справа | `news` + ручной |
| `projects_list` | Список проектов | 3 варианта (сетка / список с фото слева / полоса с прокруткой), лимит, число колонок (2–4), автопрокрутка полосы, описание, ссылка «Все проекты» | проекты (`pages` с `entity_type='project'`) |
| `team_list` | Список команды | лимит, фильтр по отделу, группировка по отделам | `team_members` |
| `cards_grid` | Карточки | вариант (иконки / категории / фото / фото сверху / компактная полоса), раскладка, описание раздела, колонки (или автоподбор без дыр), нумерация, размер и положение иконки, стиль и цвета карточек, ссылка «Все», кликабельная карточка, источник «Проекты» с отметкой «показать на главном» | ручной или `projects` |
| `media_gallery` | Медиагалерея | см. выше | `photo_albums`, `videos` |

Отметка **«Показать на главном»** (`is_featured` у проектов и фотоальбомов)
управляет тем, что попадёт в `cards_grid` и `media_gallery`. Если отмеченных
нет — блок откатывается на последние записи.

### Контейнеры

`columns` и `tabs` — контейнеры: содержимое у них не в полях формы, а во
вложенных блоках (`blocks.parent_block_id` + `column_index` = номер колонки или
вкладки). Шаблона у контейнера нет — рендер программный, с рекурсивным вызовом
`BlockRenderer::render()` для детей. Наполняются на странице: под блоком
появляется колонка на каждую ячейку с кнопкой «+ блок». Контейнер в контейнер
вкладывать нельзя — ни при добавлении (контроллер), ни при рендере.

Вкладки работают и без JavaScript: полоса вкладок — обычные ссылки на панели,
панели видны подряд, у каждой заголовок. Скрипт `blocks/tabs.js` уже поверх
этого прячет неактивные панели, расставляет роли ARIA и включает стрелки; ссылка
вида `/страница#block-12-tab-2` открывает нужную вкладку. Подписи вкладок берутся
из данных блока, поэтому переводятся вместе с ним; если вкладку удалили, её
наполнение переходит в первую, а не пропадает.

Автопереключение (`autoplay`, секунды) отсчитывает время полосой на активной
вкладке. Долю считает скрипт и отдаёт в `--cms-tabs-progress`: CSS-анимацию
пришлось бы перезапускать на каждой смене. Выбор посетителя главнее автоматики —
после клика или стрелки автопоказ прекращается насовсем; при «меньше движения»
он не начинается вовсе. Пояснение вкладки (`items[].text`) стоит над её
содержимым, а не в полосе: вторая строка в полосе ломает ряд.

Обратный порядок колонок на телефоне меняет только показ — порядок чтения с
клавиатуры и диктором остаётся авторским. Поэтому приём годится для содержимого
(«текст + фото»), а не для последовательности действий.

## Общие механизмы

- **`SectionHead`** (`app/Core/SectionHead.php`) — единая шапка секции:
  заголовок, вводный текст, ссылка «Все …» и место под инструменты. Ссылка не
  зависит от заголовка.
- **`GridBalance`** (`app/Core/GridBalance.php`) — последний ряд сетки
  растягивается, пустых ячеек справа не остаётся. Работает от 901px, ниже
  раскладку задаёт тема.
- **`ContactLink`** (`app/Core/ContactLink.php`) — телефоны и адреса почты в
  строках контактов становятся ссылками.
- **`OrgTree`** (`app/Core/OrgTree.php`) — построчные списки оргструктуры в
  дерево: отступ = уровень (до четырёх), `|` — ссылка, `*` — акцент, `-` в
  начале строки — прежний способ вложить пункт в предыдущий.
- **`BlockBackground`** (`app/Core/BlockBackground.php`) — заливка секции:
  цвет, градиент, фотография, плитка и встроенные узоры. Значения уходят
  переменными в scoped CSS блока; тот же класс собирает фон подвала
  (`BlockBackground::cssFor('.site-footer', …)`, настройки — в конструкторе
  подвала).
- **`BlockVisibility`** — расписание и ограничение по устройству.
- **`UrlGuard`** — все пользовательские ссылки проверяются перед выводом.
- **`Media::picture`** — адаптивные изображения с `srcset` и ленивой загрузкой.
  Последним параметром принимает отдельный файл для телефона: он выводится
  источником с `media="(max-width: 720px)"` перед десктопным, поэтому браузер
  скачивает ровно один кадр.

- **Общая карусель** — любой блок с `data-carousel` получает стрелки, точки,
  клавиатуру и свайп. Атрибут `data-carousel-autoplay="<секунды>"` включает
  автопрокрутку: она замирает под курсором, при фокусе внутри, во время ручной
  прокрутки, в фоновой вкладке и у посетителей, просивших меньше движения.
- **`BlockDataInput`** (`app/Core/BlockData/BlockDataInput.php`) — приведение
  полей формы: `enum()` и `int()` не пускают в данные блока то, чего не знает
  шаблон.

## Состояние

Блоков со статусом «базовый» или «средний» не осталось: у каждого
содержательного типа есть вариант вёрстки либо настройка сетки, единая шапка
секции и, где это уместно, ссылка «Все …».
