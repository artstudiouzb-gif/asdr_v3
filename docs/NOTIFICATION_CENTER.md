# Центр уведомлений

Центр уведомлений создаёт персональную ленту событий для администраторов и редакторов и при необходимости доставляет безопасную краткую версию по E-mail или в Telegram.

## Подготовка базы данных

После обновления существующей установки примените миграции:

```bash
php database/migrate.php
```

Свежая установка уже содержит необходимые таблицы в `database/schema.sql`.

## Воркер доставки

Запускайте обработчик очереди каждую минуту:

```cron
* * * * * php /path/to/project/app/Console/notification_worker.php >> /path/to/project/storage/logs/notification_worker.log 2>&1
```

Воркер защищён `ProcessLock`, поэтому наложившиеся процессы на одном сервере не отправят одно уведомление дважды. Строки очереди также получают временную аренду, а на поддерживаемых версиях MySQL/MariaDB используется `FOR UPDATE SKIP LOCKED`.

Повторные попытки выполняются через 1, 5, 15 и 60 минут. После пяти неудачных попыток доставка получает статус `failed`, но внутреннее уведомление остаётся доступным пользователю.

## Каналы и тихие часы

Каждый пользователь на странице `/admin/notifications` самостоятельно включает E-mail и Telegram, выбирает минимальный уровень важности и задаёт тихие часы.

События `critical` и `security` не задерживаются тихими часами. Обычные события остаются во внутренней ленте и откладываются для внешней доставки.

## Приватность

Во внешние сообщения не включаются:

- секретный адрес входа в админку;
- cookie, CSRF-токены и ключи интеграций;
- внутренний URL действия;
- полные поля публичных заявок;
- системный stack trace.

Подробности доступны только после авторизации в CMS. Клиент колокольчика выводит серверный текст через `textContent`, а URL действия принимается только внутри `/admin`.

## Диагностика

В Центре уведомлений супер-администратор видит количество ожидающих и неуспешных доставок. Дополнительный журнал воркера находится в `storage/logs/notification_worker.log` при использовании примера Cron выше.
