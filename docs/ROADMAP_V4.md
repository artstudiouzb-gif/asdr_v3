# Дорожная карта до v4

v4 — **релиз качества, а не новых функций**: дизайн-система, вёрстка,
производительность и безопасность. Функциональные пункты прежней карты
(`ROADMAP.md`) — электронная приёмная, OneID, выгрузка на data.gov.uz — сняты
решением владельца: будет ли приёмная использоваться вживую, неизвестно, а
строить обязательство с юридическим сроком ответа впрок незачем.

Правило, по которому написан каждый пункт, то же, что в `DESIGN_PLAN.md`:
работа попадает сюда, только если у неё есть **замер до** и **сторож после**.
Не подтвердил замер улучшение — пункт отменяется, а не «дорабатывается».
Ограничения проекта не меняются: без runtime-зависимостей, shared-хостинг, вид
собранных страниц не меняется без доказательства.

| Величина | Сейчас |

| `!important` в публичном CSS / в теме / в админке | 364 / 318 / 268 |
| жёсткие `border-radius` в публичном CSS | 89 |
| разных `box-shadow` / `border-radius` в теме | 154 / 31 |
| находки в эталоне PHPStan | 360 |

| вес `public.min.css` / `public.min.js` (brotli) | 48.8 из 52 КБ / 13.5 из 15 КБ |

Запас JS-бюджета — 1.5 КБ: любая следующая фича его съест, поэтому разгрузка
`frontend.js` стоит в плане не ради красоты.

## Этап 0 — инструменты, без которых остальное делается на глаз

1. **Срез вычисленных стилей публичной части** — близнец
   `scripts/admin-style-snapshot.mjs`: главная, лента, новость, проект, каталог,
   страница с формой, обе темы. Без него потоки 1 и 2 — правка наугад
   (`DESIGN_PLAN.md`, 1.4).
2. **Core Web Vitals с посетителей — на витрину.** `WebVitals` уже собирает
   данные; нужны p75 LCP/INP/CLS по типам страниц в «Состоянии системы».
   Цель: LCP ≤ 2.5 с, INP ≤ 200 мс, CLS ≤ 0.1.
3. **База TTFB p50/p95/p99** по протоколу E-1 (`PERFORMANCE_AUDIT_2026-09.md`).
   Снимает владелец на боевом хосте: из контейнера разработки сайт недоступен.

## Поток 2 — вёрстка

- **Сетки на `@container cms-col`**, медиазапросы — фолбэк. Сейчас
  `@container` встречается девять раз; тест 280 расширяется на все блоки с
  сеткой.
- **`!important`**: публичный CSS 364 → ≤ 200, тема 318 → ≤ 150. Семьями, под
  срезом стилей — тем же порядком, каким разбиралась админка.
- **Доступность**: в `public-layout-polish.css` и
  `public-editorial-pages.css` ноль `:focus-visible` и `prefers-reduced-motion`.
  Закрыть; в `a11y.spec.js` — страница со всеми интерактивными блоками.
- **Последние типы на схему полей**: `html`, `hero`; бюджет 2 → 0.
- **Админка**: `!important` 268 → ~100, пять BEM-классов без правил. Интерфейс
  по-прежнему не переводится — трогаем только каскад.

## Поток 3 — производительность

- **`frontend.js`** (2568 строк, одна IIFE, 43 обращения к DOM на старте):
  сначала замер длинных задач, затем инициализация по присутствию узла. Цель —
  запас JS-бюджета 3+ КБ.
- **Фасад YouTube** в тексте, `SocialEmbed` и на странице видео вместо
  ленивого iframe.
- **AVIF** — только если данные посетителей покажут, что LCP упирается в
  картинку; иначе остаётся отклонённым.
- **PHPStan**: 360 → 0 через `Database::rows()` в оставшихся моделях, затем
  уровень 8.
- **База**: EXPLAIN списков каталога и новостей на выборке от 1000 записей;
  индексы — только по находкам.
- **Lighthouse-бюджет в CI** по главной и витрине (Performance ≥ 90) —
  инструмент разработки, на сайт не влияет.

## Поток 4 — безопасность

- **Отчёты о нарушениях CSP** (`report-to` на свой адрес с ограничением
  частоты, записи — в «Журналы» с группировкой). Сейчас нарушение не видно
  нигде — тихий отказ.
- **Trusted Types в админке**: сначала report-only, боевой режим — если
  совместим редактор.
- **Пароли**: bcrypt → argon2id, если его даёт PHP хостинга; перехеширование
  через `password_needs_rehash` при входе.
- **Шифрование бэкапов**: в `Backup.php` его нет, а копии уходят на S3. Ключ из
  окружения; `RestoreDrill` обязан проверять и расшифровку.
- **Вендорные библиотеки** (`coloris`, `tabler`, `web-vitals`, редактор)
  `composer audit` не видит: манифест версий и проверка обновлений в CI.
- **`/.well-known/security.txt`** (RFC 9116) — куда сообщать об уязвимостях.
- **Аудит перед релизом — внутренний**: полный цикл навыка `security-audit`
  (отчёты в репозиторий не кладём) плюс пассивный сканер по стенду. Внешний
  пентест — отдельным решением владельца позже.

## Готовность v4.0

- p75 LCP/INP/CLS в зелёной зоне на боевом сайте;
- `!important` в публичном CSS ≤ 200, жёстких радиусов 0, PHPStan — 0 находок;
- все типы блоков на схеме полей;
- отчёты CSP подключены, за месяц — без необъяснённых нарушений;
- внутренний аудит без открытых критичных и высоких находок.

## Чего в плане нет намеренно

- Электронная приёмная, OneID, data.gov.uz — сняты владельцем (см. начало).
- `@layer` и дальнейшее дробление бандла — отклонены замером (CLAUDE.md,
  `DESIGN_PLAN.md`).
- SPA, JS-«плавная прокрутка» — запрещены правилами проекта.
- Passkeys/WebAuthn — риск закрывает TOTP, а своя реализация CBOR/COSE без
  зависимостей — отдельный крупный проект.
- Перевод админки и редизайн ради редизайна.
