# План развития после v4: функции, дизайн, расширение

v4 (`ROADMAP_V4.md`) — релиз **качества**: дизайн-система, вёрстка, скорость,
безопасность. Этот план — о том, что идёт после него: **что сайт умеет**
(функции), **как он выглядит** (дизайн) и **куда система растёт**
(расширение). Порядок внутри — по пользе для Агентства, а не по
интересности работы.

## Правила, по которым написан план

- **Замер до, сторож после.** Пункт попадает в работу, только если понятно,
  чем мерить результат и какой тест не даст ему тихо сломаться. Не подтвердил
  замер пользу — пункт отменяется, а не «дорабатывается».
- **Ограничения не меняются.** Чистый PHP без runtime-зависимостей,
  shared-хостинг, публичный рендер не ходит в сеть, акцент и шрифты — из
  админки, вид собранных страниц меняется только с доказательством.
- **Решения владельца действуют.** Электронная приёмная, OneID и выгрузка на
  data.gov.uz сняты. Правка блока прямо на сайте, «простой язык», своя
  статистика посещений, подпись релизов и отчёт вёрстки в PR — «пока не
  нужны». В план они не возвращаются без нового решения.
- **Размер работы** — S (до недели), M (две–три недели), L (месяц и
  больше). Сроков в датах нет: они зависят от того, сколько решений
  владельца потребует каждый пункт.

## Что уже есть (чтобы не изобретать заново)

Конструктор из 41 типа блоков; обложки со слайдами; новости с рубриками,
метками, опросами и подписями к фото; проекты; команда по подразделениям;
оргструктура; каталоги типов контента (на них — календарь мероприятий);
документы с реквизитами актов; формы; открытые данные; «Цели» с каруселью;
диаграммы и таблицы; поиск с журналом запросов; RU/UZ (латиница и
кириллица)/EN; публикация в Telegram, веб-пуш, e-mail-дайджест, вебхуки;
ИИ-помощник редактора; 2FA; журналы, «Состояние системы», репетиция
восстановления, обновление из GitHub.

## Направление А — функции

### А1. Мониторинг стратегии — показатели (L) ★ главное

**Зачем.** Мониторинг реализации стратегических целей («Узбекистан — 2030») —
одна из основных функций Агентства, а на сайте её нет: цифры попадают туда
только текстом новостей или вручную набранной диаграммой, которая устаревает
в день публикации.

**Что делаем.** Новый тип данных «Показатель»: цель, к которой он относится,
единица, базовое и целевое значение, **ряд значений по периодам**, источник и
дата обновления. К нему:
- страница показателя (динамика, цель, источник, методика) и страница цели со
  всеми её показателями;
- блок «Показатели» для любой страницы — выбор показателей или целиком цели;
  рисует уже существующая диаграмма (`ChartData`: полосы, доли, шкала к цели);
- загрузка значений **таблицей CSV/XLSX** в админке — показатели ведут
  аналитики, а не редакторы, и по одному полю вводить сотню значений никто
  не станет;
- выгрузка ряда в открытые данные (раздел уже есть) — CSV и JSON.

**Замер и сторож.** Число показателей с данными свежее квартала — на витрине
«Состояние системы» (устаревший показатель на госсайте хуже отсутствующего).
Тест: значение из CSV доходит до страницы и выгрузки без потерь («5,6» и
«12 400» — как у диаграммы).

**Нужно от владельца:** есть ли утверждённый перечень показателей и кто их
будет обновлять.

### А2. Реестр документов (M)

**Зачем.** Документы сейчас — блок на странице: у акта есть номер и дата, но
нет своего адреса, фильтра по виду и году, связи с другими актами.

**Что делаем.** Реестр на основе каталогов (`ContentType`): вид документа,
номер, дата, статус (действует / утратил силу / изменён), связанные акты,
ссылка на lex.uz, файлы на языках. Фильтры по виду, году и статусу; у
каждого документа постоянный адрес — его цитируют в письмах. Блок «Документы»
получает источник «из реестра» вместо ручного списка.

**Сторож:** статус «утратил силу» виден и в реестре, и в каждом блоке, где
документ выведен, — второй копии статуса нет.

### А3. Поиск (M) — уже в плане v4, поток 5

Одна письменность в индексе и запросе, основа слова для RU/UZ, набор из
30–50 контрольных запросов. После А1 и А2 поиск обязан находить показатели
и документы по номеру.

### А4. Согласование публикаций (M)

**Зачем.** Ролей две: администратор и редактор. У госоргана текст перед
публикацией обычно смотрит кто-то ещё, а сейчас это происходит вне системы.

**Что делаем.** Статус «на согласовании» между черновиком и публикацией;
роль «согласующий» (может одобрить или вернуть с комментарием); уведомление
в Telegram или почту; в журнале — кто и когда одобрил. Включается
настройкой: маленькой редакции лишний шаг не нужен.

**Сторож:** редактор без права публикации не может опубликовать ни формой, ни
массовым действием, ни через расписание — это стережёт тест прав (385).

**Нужно от владельца:** нужен ли этот шаг вообще и кто согласует.

### А5. Пресс-центр и мероприятия (M)

- **Пресс-центр:** контакты пресс-службы, пресс-кит (логотипы, фото
  руководства, справка об Агентстве — архивом), заявка на аккредитацию
  (формы уже есть).
- **Мероприятия:** регистрация участников через формы с лимитом мест,
  файл `.ics` «добавить в календарь», итоговая новость, связанная с
  мероприятием.

### А6. Подписка по темам (S)

Дайджест и веб-пуш сейчас «всё или ничего». Подписчик выбирает рубрики
новостей, типы документов и язык; в каждом письме — ссылка на эти
настройки. Таблица `subscribers` получает связи с рубриками. Сторож: письмо
не уходит подписчику на рубрику, от которой он отписался.

### А7. Английская версия и перевод-черновик (M)

EN уже есть у части страниц. Помощник-модель готовит **черновик перевода**
новости или страницы — по кнопке и в поле формы, публикует человек (правило
ИИ-помощника не меняется). Заодно — отчёт «что не переведено» по языкам:
непереведённая страница сейчас ничем себя не выдаёт.

**Нужно от владельца:** нужна ли EN полностью или только ключевые страницы.

### А8. Открытый API для чтения (S–M)

JSON для новостей, документов, показателей и мероприятий: те же данные, что
на страницах, только для других систем — ведомственных порталов, агрегаторов
новостей, мобильных приложений. Только чтение, без ключей для открытых
данных, с ограничением частоты. Вебхуки уже есть — они сообщают об изменении,
API отдаёт данные.

## Направление Б — дизайн

### Б1. Доводка типографики на Onest (S)

Шрифт и цитаты влиты (PR #119). Следующий шаг — **шкала под новый шрифт**: у
Onest крупнее строчные буквы, чем у Noto, и прежние ступени `--step-*`
читаются на ступень крупнее. Замер: ширина строки в знаках и высота
заголовков на 1440 и 390px до и после. Заодно — табличные цифры в датах,
номерах и показателях и правильный узбекский апостроф (`ʻ`, U+02BB) в
«Oʻzbekiston» — сейчас он зависит от того, как набрал редактор.

### Б2. Компоненты тем же языком (M)

Шаги очереди 5 из `DESIGN_PLAN.md`, которые не зависели от отклонённого
«смелого элемента»: новости «главная и список» вместо мозаики из одинаковых
карточек, направления списком без номеров 01/02, документы реестром
(вместе с А2). Каждый шаг — отдельный PR со снимками до и после и вашим «да».

### Б3. Страница показателя как образец (M, вместе с А1)

Первая страница, спроектированная с нуля под новый язык: цифра, динамика,
цель, источник. Здесь цифры — **содержание**, а не украшение, поэтому это
законное место для крупных чисел.

### Б4. Фото и иллюстрации (S)

Правила для редакторов: пропорции кадра по местам вывода, фокус лица,
минимальный размер, что делать без фото (эмблема-заглушка уже есть).
Проверка при загрузке: предупреждение в форме, если снимок меньше места, где
он будет показан.

### Б5. Доступность выше минимума (M)

axe в CI уже проверяет A и AA. Дальше — то, чего axe не видит: порядок
табуляции на ключевых страницах, осмысленность подписей для диктора,
проверка с настоящими экранными чтецами (NVDA, VoiceOver) на пяти сценариях:
найти документ, прочитать новость, узнать показатель, подписаться, найти
контакты.

### Б6. Справочник редактора (S)

Страница в админке «Как собирать страницы»: какие блоки для чего, живые
примеры (витрина `/visual-regression` уже собирает их), типичные ошибки. Это
дешевле, чем объяснять одно и то же каждому новому редактору.

## Направление В — расширение платформы

### В1. Тиражирование: CMS как продукт для других ведомств (L)

**Зачем.** Всё, что сделано для Агентства, годится любому госоргану:
конструктор, переводы, безопасность, обновление из GitHub. Установщик,
демо-контент, шаблоны страниц файлом и обновление по релизам уже есть.

**Чего не хватает:**
- **чистая установка без Агентства**: сейчас демо накладывает фикстуру
  реального контента Агентства (`agency_content.php`) — для другого
  заказчика нужен нейтральный набор;
- **бренд целиком из настроек**: эмблема, цвета и шрифты уже настраиваются;
  проверить, что имя Агентства не зашито нигде в шаблонах и словарях;
- **документация установки и администрирования** для чужой команды;
- **канал обновлений**: каждая установка сама проверяет релизы (`Updater`
  уже умеет) — нужно правило версий и заметки к релизам на языке владельца.

**Сторож:** тест «чистая установка» — установщик на пустой базе без
фикстуры Агентства, обход smoke без ошибок.

**Нужно от владельца:** планируется ли это вообще. Если нет, пункт не
делаем: мультиарендность без заказчика — лишняя сложность.

### В2. Подсайты проектов и регионов (L)

Отдельные разделы с собственной шапкой, меню и адресом (`site.uz/proekt` или
поддомен) внутри одной установки: у крупной программы или регионального
офиса своя аудитория, но редакция и медиатека общие. Сначала — через раздел
с собственным меню и шапкой в пределах одного домена; поддомены — только
если хостинг позволит.

### В3. Инфраструктура под рост (M)

- **Нагрузка:** замер под нагрузкой — сколько запросов в секунду держит
  shared-хостинг на главной и ленте с кэшем и без. Решение «переезжать ли на
  VPS» принимается по этому замеру, а не заранее.
- **CDN для медиа** (поддержка уже есть — `Asset::rewriteMedia`) — включить,
  когда медиатека станет главной частью трафика.
- **Внешний мониторинг** (`MONITORING_HEARTBEAT_URL`) — подключить на бою,
  если ещё не подключён: без него о падении сервера узнают посетители.

### В4. Приложение без магазина (S)

Манифест уже отдаётся. Довести до устанавливаемого PWA: офлайн-страница с
контактами и последними новостями, иконка на экран телефона, пуш уже есть.
Отдельное мобильное приложение не нужно: оно дублировало бы сайт и
требовало публикации в магазинах.

### В5. Интеграции (по запросу)

lex.uz (ссылки на акты, А2), календари (`.ics`, А5), социальные сети кроме
Telegram — только если Агентство там реально ведёт аккаунты. Каждая
интеграция идёт через воркер или админку, а не через публичный рендер
(правило теста 110).

## Порядок

```
v4.x   качество — ROADMAP_V4.md (идёт сейчас) + Б1 типографика
v5.0   А1 показатели + Б3 страница показателя + А2 реестр + А3 поиск
v5.1   Б2 компоненты + А6 подписка по темам + А8 API
v5.2   А4 согласование + А5 пресс-центр + Б5 доступность + Б6 справочник
v6.0   В1 тиражирование и/или В2 подсайты — по решению владельца
по ходу: Б4 фото, В3 инфраструктура, В4 PWA, В5 интеграции
```

Почему так: показатели и реестр — то, ради чего сайт Агентства существует;
поиск без них искал бы не то. Дизайн идёт вместе с функциями, а не отдельным
«редизайном»: новый язык проверяется на новых страницах. Расширение — в
конце, потому что тиражировать имеет смысл отлаженную систему.

## Готовность v5.0

- показатели с данными на сайте, у каждого — дата обновления не старше
  квартала; ряд доступен в открытых данных;
- у каждого документа реестра постоянный адрес и статус;
- контрольный набор запросов поиска находит нужное первым в 80 % случаев;
- p75 LCP/INP/CLS в зелёной зоне и на новых страницах.

## Что нужно решить владельцу

1. **Показатели (А1):** есть ли утверждённый перечень и кто будет обновлять
   данные? Без этого А1 не начинаем — пустой раздел показателей хуже, чем
   никакого.
2. **Согласование (А4) и английский (А7):** нужны ли?
3. **Тиражирование (В1):** планируется ли ставить систему другим ведомствам?

## Чего в плане нет намеренно

- Электронная приёмная, OneID, data.gov.uz — сняты владельцем.
- Правка на сайте, «простой язык», своя статистика, подпись релизов, отчёт
  вёрстки в PR — владелец решил, что пока не нужны.
- SPA, JS-«плавная прокрутка», `@layer` — отклонены правилами и замерами
  проекта.
- Отдельное мобильное приложение — его заменяет PWA (В4).
- Внешний поисковый движок — поиск остаётся на MySQL, пока замер не
  покажет, что тот не справляется (А3).
