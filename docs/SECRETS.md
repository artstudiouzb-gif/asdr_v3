# Ротация секретов (группа 6)

Процедуры замены чувствительных ключей ArtStudio CMS. Главный ключ шифрования,
SMTP и аварийный Telegram читаются из `config/config.php`/окружения. TOTP,
токены интеграций, VAPID private key и секреты webhooks хранятся в БД только
в зашифрованном виде — см. `crypto`-блок и `SECURITY.md`.

## `encryption_key` (APP_ENCRYPTION_KEY)

Используется для симметричного шифрования чувствительных настроек в БД
(например, токенов соцсетей). Ротация:

1. **Не удаляйте старый ключ сразу** — иначе уже зашифрованные значения станут
   нечитаемыми.
2. Сгенерируйте новый ключ: `php -r 'echo bin2hex(random_bytes(32)), "\n";'`.
3. Новый ключ укажите как `APP_ENCRYPTION_KEY`, старый — временно как
   `APP_PREVIOUS_ENCRYPTION_KEY` (или в одноимённых полях `crypto` в config.php).
4. Запустите `php database/encrypt_secrets.php`. Команда работает в одной
   транзакции и перешифрует TOTP, API-токены, VAPID private key и webhooks.
5. Проверьте вход с 2FA и интеграции, затем удалите старый ключ.

Для первой миграции старой установки: добавьте ключ, выполните
`php database/migrate.php`, затем `php database/encrypt_secrets.php`. Новые
установки получают случайный ключ автоматически. Резервную копию ключа храните
отдельно от дампа БД: без него восстановить зашифрованные значения невозможно.

## Токены соцсетей (Facebook / LinkedIn / Instagram)

Хранятся в настройках раздела `/admin/social` (супер-админ). Ротация: получите
новый токен у провайдера, вставьте в поле токена, сохраните. Старые публикации
(`social_posts`) не требуют перевыпуска. При компрометации — сначала отзовите
токен на стороне провайдера, затем впишите новый.

## Секреты вебхуков (`webhooks.secret`)

HMAC-подпись `X-ASDR-Signature` считается на основе секрета вебхука.
Ротация: обновите секрет в `/admin/webhooks` **и** у получателя одновременно
(иначе подпись перестанет сходиться). Доставки в очереди, подписанные старым
секретом, при ретрае будут переподписаны текущим.

## Пароли администраторов / подтверждение входа

- Сброс пароля: `/admin/login` → «Забыли пароль» (токен со сроком 30 мин) или
  CLI `php database/create_admin.php` для нового супер-админа.
- Второй фактор: приложение-аутентификатор подключается в профиле
  (`/admin/profile`), привязка Telegram-бота — там же или в разделе
  `/admin/telegram`. Достаточно любого канала; оба доступны и в файловом
  портале (`/repo/security`).
- При компрометации сессии — раздел «Активные сессии» отзывает доступ мгновенно
  (серверный registry).

## SMTP / Telegram

SMTP-логин и пароль задаются в `config.php`/окружении (`SMTP_*`). После
ротации обновите значение и перезапустите PHP-FPM либо дождитесь нового
процесса. Аварийный канал логов использует `TELEGRAM_BOT_TOKEN` и
`TELEGRAM_CHAT_ID` из окружения/config.

Основной Bot API токен для входа, уведомлений и публикации настраивается в
`/admin/telegram` и хранится в БД под ключом `telegram_bot_token` в
зашифрованном виде. При ротации сначала отзовите старый токен у BotFather,
затем сохраните новый и выполните встроенную проверку подключения.

## Версионирование миграций

Отдельная таблица `schema_migrations` не нужна: применённые миграции
фиксируются в таблице `migrations` (`database/migrate.php`), которая играет ту
же роль — `php database/migrate.php status` показывает применённые и новые.
